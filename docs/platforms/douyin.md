# 抖音接入与运维

登录、签名、收藏读取与下载由 Rust 原生 HTTP 完成，不需要浏览器或远程签名服务。现有 B 站认证、任务调度器、媒体表、播放器及观看记录继续复用。

平台接口和风控可能变化，真实扫码、下载、目标设备和长期运行需独立验证；离线检查不能代替这些验收。

## 数据与接口

媒体继续使用 `video`、`page` 和 `watch_progress`，新增 `platform/platform_id`，抖音不填造 BV、CID 或 B 站作者 ID。B 站来源唯一性保持原语义；抖音作品 ID 使用字符串并全局唯一。

| 新表 | 职责 |
|---|---|
| `douyin_account` | 单账号绑定、拒绝计数、暂停原因、冷却与运行时间 |
| `douyin_folder` | 勾选状态、启停版本、完整基线及最近结果 |
| `douyin_folder_item` | 每夹曾见 ID、当前是否存在、是否在该夹获得新增下载资格 |
| `douyin_download` | 按本地分页 ID 保存下载状态及连续失败次数，不使用 B 站任务位字段 |

完整扫描在事务内提交；启停版本变化则放弃该次提交。只有当前勾选夹中的合格条目进入已有媒体状态，不新增队列表。另一夹的历史基线不能替停用夹提供下载资格。

现有二维码接口增加可选 `platform`，默认 B 站。抖音增量接口为 `/douyin/status`、`/douyin/resume`、`/config/douyin`、`/video-sources/douyin` 及其刷新/选夹操作、`/task/douyin`；均位于既有 `/api` 认证与 CSRF 保护之内。

平台清单、公共媒体状态和升级兼容性见 [多平台隔离](../development/platform-isolation.md)。前后端需同步升级，旧客户端不能继续解释公共响应中的下载任务数组。

## 使用规则

- 一个抖音账号，仅扫描勾选的收藏夹。首次完整扫描只记录该夹历史，不下载历史视频；后续按作品 ID 差集识别新增，作品发布时间不影响资格。
- 每夹保留曾见 ID，移出再移回不会重复保存。不同夹分别建立基线，通过媒体唯一约束只保存一份成品。取消勾选保留历史与文件，恢复时补齐仍在夹中的新增。
- 抖音独立间隔默认 1800 秒，与 B 站任务共用调度器。一个账号的登录、列夹、扫描及下载串行；重叠周期跳过。
- 两平台共享整机资源上限：同时最多 2 个文件传输、1 个 ffmpeg/ffprobe 进程。资源繁忙时等待，不增加失败次数或拒绝计数；已有平台限流和并发配置仍然生效。
- 一轮遇拒绝立即停止，下一周期再试；三轮拒绝后暂停。完整正常周期清零；普通网络错误不增加也不清零。登录失效、验证码、账号身份不符、磁盘不足需要人工处理。
- 普通下载失败最多四次；明确点击“重试抖音同步”会重新启用当前勾选夹中已有资格的失败项。它不能补下基线历史，不能越过暂停或冷却。
- 仅支持视频，不下载图文、实况照片、直播；不提供历史批量下载、强制清理重下或网页远程验证码。

## 安装与部署

先按[升级与回退](../operations/deployment.md)备份并停止实例，再更换程序。相关迁移保留原媒体主键、文件路径与观看引用；为避免丢失抖音历史，迁移不提供自动降级。回退版本应同时还原升级前数据库备份，不能用旧程序直接写升级后的库。

当前源码运行依赖为 ffmpeg 和 ffprobe；签名、二维码和会话恢复均由 Rust 直接完成，不启动浏览器、Python／Node 或远程签名服务。升级时保留 B 站路径、现有媒体、观看进度及两平台基线，先在独立副本验证。

```sh
# 已安装项目工具链与前端依赖时
cd web
bun run check
bun run build
cd ..
cargo build --release --locked -p favkeep --bin favkeep
```

沿用现有 `FAVKEEP_CONFIG_DIR`、`FAVKEEP_APP_ORIGIN` 及管理员认证配置。配置新增以下非凭据字段，旧配置缺省时自动补齐：

```json
{
  "douyin": {
    "interval": 1800,
    "path": "/absolute/private/media/douyin"
  }
}
```

后台左侧并列“B站”和“抖音”，入口分别为 `/platforms/bilibili` 和 `/platforms/douyin`。两个平台都按“连接账号 → 收藏来源 → 同步任务”组织，账号、选夹、独立间隔、手动运行及恢复操作集中在平台内；B站另有下载设置，管理文件保存、视频处理、弹幕和并发。通用设置只保留服务地址、通知和管理员密码。步骤写入 URL，支持刷新和返回；旧 `/video-sources` 地址跳转到 B站收藏来源，带 `platform=douyin` 时跳转到抖音。视频管理和观看页显示平台，原站链接使用真实作品 ID。

媒体路径可以通过现有受保护配置接口设置，必须是绝对路径。旧 `browser` 字段兼容读取、但不再生效，也不要求路径有效。ffprobe 默认从 PATH 获取；指定 `FAVKEEP_FFMPEG_PATH` 时，在同目录寻找 ffprobe。磁盘需额外保留至少 64 MiB，下载前检查可用空间；写入时再次捕获磁盘满错误。

## 会话与人工验证

凭据保存在 `$FAVKEEP_CONFIG_DIR/douyin/auth.json`，Cookie 保留域、路径、Secure／HttpOnly／SameSite 及过期时间；Unix 私有目录 0700、文件 0600，Windows 核对 ACL。旧浏览器凭据格式兼容读取，必须通过官方本人接口重新验证；不能恢复时重新扫码，保留原凭据、来源基线和文件。

网页显式连接总是使用新的内存 Cookie 存储，直接申请官方二维码并轮询。官方同账号核验成功后，核对管理员会话及取消状态，再原子替换凭据；过期、异号、取消或验证失败保留旧凭据。关闭弹窗、退出管理员或会话到期会取消登录，包括等待账号锁的任务。正常同步恢复已存会话、申请实时令牌并核对官方本人身份，不隐式申请二维码；状态查询不创建账号、登录或扫描。

平台验证要求或拒绝立即停止，不自动回退到其他登录接口。已绑定账号沿用原暂停和冷却；首次绑定前的登录拒绝也持久记录冷却，反复点击不能跳过。旧 `browser/` 资料保留但不使用。`--douyin-import-session` 已知存在 TLS 初始化顺序问题，当前使用网页扫码，不将 CLI 导入作为恢复指引。

## 文件与恢复

成品目录为 `<douyin.path>/<作品ID>/`，其中 `video.mp4` 供原播放器读取，`poster.jpg` 从本地视频提取；封面失败不阻止播放。沿用现有 Range、HEAD、观看进度及继续观看接口。

新配置可通过 `--media-root`／`FAVKEEP_MEDIA_ROOT` 将抖音与小红书媒体放到共同父目录下；已有路径与 B 站路径不变。部署示例见 [三平台媒体目录](../operations/media-paths.md)。

视频先写同目录 `video.part`，检查传输长度和 ffprobe 后，写入完成标记，再以不覆盖已有文件的方式发布 `video.mp4`。Unix 在登记成功前同步目录。重启时，已有有效成品直接登记；仅带匹配长度完成标记的暂存文件允许恢复。未完成暂存重新下载，成功文件不覆盖。损坏的正式文件保留，需人工检查后处理。

## 日志与任务统计

抖音的账号连接、收藏夹刷新与启停、同步间隔修改、手动同步、失败重试、连接恢复、逐夹扫描和逐条下载统一使用 `[抖音]` 前缀，进入现有 tracing、WebSocket 和日志页。二维码就绪每次登录任务只记录一次；只读列表与状态轮询不产生业务日志。日志只包含固定错误原因、收藏夹名称与作品标识，不记录凭据、二维码内容、任务密钥、签名媒体地址或原始响应。成功保存日志在媒体校验、发布和数据库登记之后输出。

`GET /api/douyin/status` 保留原字段，在 `task` 内增加：

- `current`：空闲时为 `null`；运行时包括 `operation`（`login`、`refresh`、`sync` 或 `resume`）、`stage`、当前 `folder` 和 `video`。账号锁仍防止并发操作；登录排队时显示当前正在占用账号的操作。
- `last_sync`：本进程尚无同步时为 `null`；包含起止时间、已提交扫描条目、历史跳过、已有条目、不支持条目、新增入库、新下载、成品复用、中断恢复、失败、剩余待处理数量和最终错误码。同步期间持续更新，部分失败保留已完成部分；取消也清除当前操作并记录中断。

扫描条目按收藏夹累计，历史、已有、不支持及新增入库互斥；跨夹重复仅新增入库一次。扫描计数在事务提交后更新，回滚不增加计数。新下载仅指本轮下载、校验、发布并登记的视频；复用及恢复单列，不计入新下载。剩余待处理仅包括当前来源允许、未暂停或冷却且未达到失败重试上限的条目；暂时无法确认时为 `null`，页面显示“未知”。

当前操作、最近摘要与日志缓冲均在进程内；重启后不补造历史统计。服务器回放最近 200 条日志，不新增日志持久化或数据库迁移。来源页明确提示首次建立基线跳过历史，重新启用沿用原基线；扫描完成不代表本轮有新下载。

## 验证与来源

```sh
cargo test --locked -p favkeep --bin favkeep
cargo test --locked -p favkeep --example protocol_probe
cargo clippy --locked -p favkeep --bin favkeep -- -D warnings
```

`protocol_probe --douyin-passport --douyin-application` 直接执行当前业务客户端，验证登录、会话恢复、收藏读取与媒体下载。下载验证要求作品出现在同账号已完整扫描的指定夹快照中；该工具不打开应用数据库，不创建生产下载资格。

旧 A-Bogus 开发参考与必要接口参数参考 F2 固定提交 `f6be8c0ffba9a127075bbeafe4838716650b6325`，现位于 `examples/protocol/legacy_sign.rs`，保留 Apache-2.0 许可、修改说明和离线对照向量。`scripts/generate_douyin_sign_vectors.py` 仅用于重新生成这些数据；当前生产使用 `src/douyin/native/` 的原生实现。catbus、xhshow 等来源及各自许可证见仓库根目录的 `THIRD_PARTY_NOTICES.md`。

支持范围和验证边界见[支持范围与开源检查](../development/open-source.md)。
