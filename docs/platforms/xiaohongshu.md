# 小红书视频收藏：50 条检查窗口

当前由 Rust 原生 HTTP 完成登录、会话恢复和窗口同步。只检查前 50 个不同条目，不能保证窗口外新增或长期会话持续可用。

真实扫码、新收藏下载、目标设备与长期运行须单独验证；历史结果不代表当前版本已重新实测，边界见[支持范围与开源检查](../development/open-source.md)。

## 使用

媒体保存到 `<xiaohongshu.path>/<作品ID>/video.mp4`，本地封面为同目录的 `poster.jpg`。新配置支持 `--media-root`／`FAVKEEP_MEDIA_ROOT` 指定共同父目录；已有路径与 B 站路径不变，详见 [三平台媒体目录](../operations/media-paths.md)。

在“小红书 → 连接账号”生成新的官方网页二维码，用手机扫描并确认。当前代码使用新的内存 HTTP 会话申请二维码，身份经官方本人接口核对后，才更新持久凭据。关闭弹窗、管理员退出、过期或异号不会替换旧凭据。首次未绑定账号时的拒绝也会记录冷却。

随后启用唯一的“全部收藏”来源。来源默认停用，默认间隔 1800 秒。首次成功读取前 50 个不同 ID，只记录历史，零下载；不足 50 条必须取得可靠终页。图文占窗口位置，记为不支持，不下载。

后续窗口须与上次窗口有重叠。只有第一个永久已见条目之前、从未见过的连续前缀中的视频取得下载资格。末尾补位、已见旧条目重新排序、重复扫描及重新收藏不会重新取得资格。完全无重叠时自动重设起点，本批不下载，已取得的下载资格继续保留。

停用期间不执行扫描或下载，重新启用继续遵守窗口规则。取消收藏、滑出窗口、重设起点和停用均不删除成品、资格或观看记录。窗口之外的新增可能遗漏，历史排序变化也可能无法区分，因此界面称“新发现视频”。窗口顺序来自原站，不推算收藏时间。

普通下载最多失败四次，之后仅由明确的“同步并重试失败项”或单条失败重试重新排队。平台拒绝停止本轮并冷却，连续三轮拒绝后暂停；登录失效、身份异常、验证要求或满盘直接暂停。登录、恢复和手动任务均不能绕过冷却。

## 实现边界

- 小红书运行时为 Rust HTTP 客户端、SQLite 和原调度器，签名在 Rust 内计算；未加入 Python／Node 服务。直接读取官方分页 JSON 并核对账号和游标。旧 `browser` 配置兼容读取但不再生效，不需要浏览器运行时。
- `xiaohongshu` 模块分别管理登录、窗口扫描、已见记录、资格、下载及进度，账号锁与抖音分开。复用已有私有文件函数及整机传输、媒体处理许可；真正共用的媒体校验、完成标记和无覆盖发布集中到 `media_file`。
- 相关迁移使用专用单连接执行表重建，事务内核对旧值、恢复索引／视图／序列并检查外键，失败回滚。未修改已发布迁移；B 站、抖音及观看记录保留。
- 窗口、已见记录、新增资格与扫描统计同一事务提交，启停版本冲突、身份异常或分页失败不推进起点。已见 ID 永久保留，下载资格独立于当前窗口存在。
- 视频使用字符串平台 ID，单作品一个分页，BVID／CID 留空。旧表必须填写的日期使用内部未知值占位，不作为收藏时间展示，也不参与窗口或新增判定。
- 下载重新请求详情，选择已确认的 H.264／Rednote EF4 MP4 候选，再以 ffprobe 验证；不做转码。媒体仅访问实测白名单中的 HTTPS CDN，每次重定向重验，不向 CDN 发送账号 Cookie。签名 URL、Cookie 和访问令牌不进入普通响应或日志。
- 成品无覆盖发布，长度、ffprobe 和同步完成标记校验后才登记成功；重启可复用成品或恢复已完成的暂存文件。重新传输先清除旧完成标记，本地封面失败不影响播放。
- 状态接口只读。全部新增接口沿用管理员认证、CSRF 和 Origin 防护。公共筛选、计数、分页、播放、封面和观看进度支持三平台；B 站专属操作继续拒绝其他平台。

## 接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/xiaohongshu/status` | 账号、冷却、独立间隔、任务阶段与已提交统计 |
| `POST /api/xiaohongshu/resume` | 冷却结束后验证同账号并恢复 |
| `GET /api/video-sources/xiaohongshu` | 读取唯一来源，不触发扫描或登录 |
| `PUT /api/video-sources/xiaohongshu` | `{ "enabled": true/false }` |
| `PUT /api/config/xiaohongshu` | `{ "interval": 1800 }`，窗口固定为 50 |
| `POST /api/task/xiaohongshu` | 明确手动同步并重试符合规则的失败项 |
| 原二维码生成／轮询接口 | `platform=xiaohongshu`；轮询请求支持 `cancel=true`，必须匹配管理员会话和随机任务键 |

配置保留独立 `xiaohongshu.interval/browser/path`，旧配置自动取得默认值。当前代码普通同步直接验证已存会话，显式登录使用全新的私有内存 Cookie 容器；`browser` 兼容读取但对小红书不再生效，也不要求它是有效路径。Cookie 保存域、路径、过期、Secure、HttpOnly 与 SameSite 信息，只有官方本人核验及管理员会话复核成功后才原子替换凭据。

## 验收与回退

离线验证及浏览器模拟回归不替代手机扫码、真实新增下载或无人干预运行。真实验收顺序为：全新网页扫码 → 启用来源 → 首次窗口零下载 → 新收藏一条旧作品 → 自动保存 → 人工听音与拖动 → 刷新续播 → 重复同步无重复 → 重启恢复，再按默认间隔完成三轮无人干预扫描并核对其他平台。

更新前停止实例，成组备份数据库、配置、凭据和旧程序；先在独立副本演练迁移并校验业务行，再按[升级与回退](../operations/deployment.md)切换。回退必须停止新程序并恢复匹配的程序与数据库，不能让旧程序写升级后的库。

不提供全量历史、历史补下载、专辑选择、图文阅读、转码或正式发布。清晰度取决于平台网页实际返回的候选流，不承诺原始或最高画质。
