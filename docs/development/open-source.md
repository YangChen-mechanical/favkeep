# 支持范围与开源检查

当前交付为开发中的自托管源码，安装和限制以[项目首页](https://github.com/YangChen-mechanical/favkeep)与[快速开始](../quick-start.md)为准。仓库工作流只构建候选产物，不自动发布文档站、二进制或容器。

## 支持与验证边界

- 单管理员实例，共用应用会话保护 API、媒体和 WebSocket；不支持多租户。
- B 站保留来源同步能力；抖音按已选收藏夹建立完整基线，小红书处理最近 50 条窗口。首次基线、下载资格及恢复按各平台文档执行。
- 既有验证覆盖 Windows GNU 与 Linux ARM64 的部分版本和场景，不表示当前提交已在所有设备重新实测。真实扫码、下载、长期运行与公网安全须分别验证。
- 离线测试、模拟接口和文档构建不能代替真实平台、目标设备或公网部署验收。平台拒绝、限流或验证要求需人工处理。

## 公开内容

公开源码保留使用、架构、开发检查、平台规则和通用运维说明。个人服务器记录、原始设计、逐轮验收、数据库、凭据和日志不属于公开交付。

内部文档同时由 Git 忽略规则和文档站排除规则隔离；新增内部资料时须同步维护两者。仅从侧栏移除页面不能防止它进入构建或搜索索引。

## 复查方法

在只包含候选公开引用的干净检出中，使用 Gitleaks 8.30.1 或兼容版本复查：

```sh
gitleaks git . --log-opts=--all --redact
```

源码快照使用 `git archive` 导出到独立目录，再使用仓库的扫描配置：

```sh
gitleaks dir /path/to/source-snapshot --config .gitleaks.toml --redact
```

保留扫描器默认规则；现有 SQL 误报排除只适用于已核对的精确片段。另检查个人服务器地址、路径、平台会话和账号数据，不把运行目录或依赖缓存混入源码快照。发现真实凭据时先撤销或更换。

文档检查命令见[开发说明](README.md)。确认公开页面、链接、构建产物和搜索索引不含内部正文，同时检查许可证及第三方来源链接。

## 历史与分发

历史清理会改变提交号。旧私有仓库、工作树和备份仅供内部追溯；不要整体推送或合并回公开分支，需要的改动应重新移植并扫描。远端缓存、PR 引用、附件、Actions 日志和既有副本须另行检查，本地清理不能使其自动消失。

源码扫描不能证明不存在所有秘密。公开前复查全部远端分支和标签，避免带回旧历史。发布二进制或容器前，另核对实际链接或分发的依赖、FFmpeg 及基础镜像许可证；第三方来源见[第三方说明](https://github.com/YangChen-mechanical/favkeep/blob/favkeep/THIRD_PARTY_NOTICES.md)。
