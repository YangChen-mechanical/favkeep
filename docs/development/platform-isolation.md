# 多平台隔离与公共媒体状态

## 模块与身份

B 站的来源适配、同步工作流和下载上下文位于 B 站模块；抖音独立管理登录、完整基线、收藏资格、冷却和下载状态。共用本地媒体表、播放、观看记录和进程内资源限制。各平台的增量规则与去重方式保持原样：B 站按来源记录，抖音跨夹保存一份媒体。取消收藏或停用来源不会新增删除本地文件的行为。

外部作品身份由平台和字符串 `platform_id` 一起确定；本地引用继续使用原有 video/page 主键。未知平台被拒绝，不回退到 B 站。新增平台需要明确实现平台枚举分支、平台专属面板、同步流程和必要迁移；不提供动态插件机制，小红书图文不在当前支持范围内。

## 公共接口

`GET /api/platforms` 在既有认证保护内返回平台 ID、名称和能力。公共导航、名称和筛选项读取此清单；账号、来源、任务面板按平台注册。能力表示实现支持的功能，操作资格根据当前记录重新检查。

视频和分页响应提供：

| 字段 | 语义 |
|---|---|
| `download_state` | `waiting`、`succeeded`、`failed`，汇总该平台适用任务 |
| `media_ready` | 内容下载成功且登记了 MP4 播放路径；实际读取仍检查本地文件及路径权限 |
| `source_url` | 视频的原站链接，由后端按平台生成；没有有效作品 ID 时为空 |
| `allowed_actions` | 当前记录允许的操作；执行时后端重新检查 |
| `platform_details` | 带 `platform` 标记的专属详情：B 站任务状态，或抖音失败次数 |

分页的原站链接和操作入口由所属视频提供。公共响应不再提供顶层五段 `download_status` 数组；B 站数组只存在于 `platform_details`。B 站附属任务失败时，视频可以同时为 `download_state=failed`、`media_ready=true`。抖音没有弹幕、字幕等伪成功任务。

列表的状态筛选在数据库计数、分页之前执行。`playable_page` 数据库视图集中描述可播放资格，供列表、详情、观看统计、继续观看、观看进度写入和媒体读取使用。文件读取仍执行现有授权、路径和文件检查，保留 Range 与 HEAD 支持。

B 站状态编辑、强制重置、清理重下及批量状态接口明确检查 B 站平台。抖音单条重试与同步任务的批量失败重试使用同一资格检查：仅当前选中且可用来源中的合格失败项可重试，不越过暂停或冷却。失败不足四次自动重试，第四次失败后等待明确操作。

## 整机资源

当前生产源码进程内最多 2 个文件传输、1 个 ffmpeg/ffprobe 进程；平台原有并发与限流继续生效。这些默认值固定，不新增配置字段或调参界面。

分块请求分别持有传输许可直到响应体写入结束；探测回退前释放探测许可。传输结束再申请媒体处理许可。两平台登录、恢复及接口签名均使用 Rust HTTP，不需要浏览器运行时。取消和管理员退出会释放登录任务及账号锁。资源等待写入日志，不记为平台失败或拒绝。并发上限不构成进程内存上限。

## 升级与回退

停止旧实例并备份数据库，在副本验证后同时升级前后端。相关事务迁移将抖音内容状态映射到 `douyin_download`，保留失败次数并清零遗留 B 站任务位；缺失、额外分页或无法解释的内容状态使迁移失败回滚。迁移保留主键、路径、观看记录与收藏基线，不触碰媒体文件，同时回填缺失的 B 站作品 ID。

原配置字段保持不变。公共响应调整不兼容旧客户端；回退时必须还原升级前的数据库备份，旧程序不得直接写入新库。真实账号与生产部署验收应单独记录，模拟接口浏览器测试不代表平台协议或长期稳定性验收。
